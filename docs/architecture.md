# 架构与原游戏数据映射

## 本版的数据路径

```text
明确标记的演示数据 → Snapshot → AppState / 纯状态转换
                                      ↓
                         Node UI 树 → AstroBox V4 Host UI
                                      ↓
                root/data/state.json / 上一有效版本
                                      ↓
             BackupRecord → JSON + SHA-256 → 系统保存窗口
```

[数据契约](../src/contracts.rs)、[演示网关实现](../src/demo.rs)、[状态转换](../src/state.rs)、[持久化](../src/store.rs)和[原生适配](../src/runtime.rs)相互分离。真实设备接入可在现有快照契约前加入读取网关，保持 UI 与本地备份层稳定。

## 四页与三档布局

- 战绩与详情共享当前选中模式、对局和快照。
- 特勤处包含库存、设施和任务子视图。
- 设置拥有连接、保留策略、备份预览／恢复与导出入口。
- UI 以实际容器宽度分为手机 `<640`、平板 `640–1023`、电脑 `≥1024` 三档。
- 纯渲染函数产生可测试的 [Node 树](../src/view.rs)；V4 适配器用公开 Element Builder 转换，并通过尺寸查询在窗口变化时更新布局。

## 只读参考的原游戏

源码参考：https://github.com/taskschd1145/deltaforce-watch-vela ，参考版本 1.2.2.4。

| 原游戏领域 | 读取到的能力 | 同步器契约 |
| --- | --- | --- |
| 烽火行动状态 | result、kills、map_id、variant，物资及结束伤势 | 模式、结果、地图难度、击杀、结算物资快照 |
| 全面战场士兵状态 | result.stats、score、xp_gain、elapsed 时间 | 积分与经验独立保存，统计独立显示 |
| profile v6 | stash、资金、等级、仓库／训练等级、耐久、锁定 | 库存、玩家和设施摘要 |
| 当前／备份／pending 槽 | 保存事务的有效版本 | 后续一致性快照读取的事务基础 |

### 历史与时间

原游戏的保存槽用于当前状态与事务恢复。同步器历史列表采用独立的 MatchRecord 集合，开局时间有明确字段与来源。后续设备端应在实际开始行动时记录时间，在结算时固定保存战绩快照。

### 物资与货值

原游戏背包、详情和位置数组按索引共同表达物资；来源、数量、穿戴与安全箱决定结算结果。失败时安全箱可能保留新搜获价值。同步器记录完整物资与当时单价，`lootValue` 为整数总和，便于历史展示。

### 承伤与结束伤势

五类部位为 `head / chest / abdomen / arm / leg`。原游戏的 damage 会随治疗减少，用于表达结束时伤势。同步器把它与累计承伤拆分为 `injuryAtEnd` 和 `damageTaken`；后续设备端采集累计承伤时使用独立计数。Demo 两种数据均显式来自示例。

### 设施与任务

真实设施概念使用仓库、训练中心；部门任务的来源为 `demo-extension`，用于预演任务阅读与筛选流程。

## 备份与事务

- 查看备份使用临时预览 ID，预览与当前持久化快照分离。
- 恢复、删除及清理保留策略有确认步骤。
- 保存前复制 UI 状态，持久化成功后提交候选状态；失败时保留原快照和策略。
- 本地文件保存限制在插件自身目录，采用结构边界校验、严格 JSON 解码、临时文件 flush/sync、原子替换与上一有效版本保留。
- 数据损坏时提示检查并保留现场；已有损坏文件的覆盖需要后续显式恢复流程。
- 外部导出副本由玩家单独管理，插件保留策略管理内部备份集合。

## 后续真实设备接入

建议由设备端提供版本与能力列表、一致性只读快照、历史统计，并负责恢复事务的最终验证。原游戏的资产预留、结算回执及当前行动应处于同一一致性边界。

本版的网关行为通过模拟连接展示；真实通信、设备授权和端到端恢复作为后续独立迭代验收。
